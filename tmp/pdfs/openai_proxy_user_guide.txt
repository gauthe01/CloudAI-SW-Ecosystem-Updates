Brief
This page describes how to use the OpenAI Proxy https://openai-api-proxy.geo.arm.com/ and get started using API
keys. This service is in active development and there may be many areas that are subject to change as we attempt to
add new features or improve usability.
Overview
The purpose of the proxy is two-fold - briefly (and not exhaustively)
FinOps perspective
being able to behind-the-scenes cache model request output and replay
work out where requests are coming from and how much they are costing
Security perspective
stopping Arm OpenAI keys from being directly known to Arm employees
they will work from anywhere and have no max time to live, creating a problem of accidental leakage
- there are already many attacks of "LLM jacking" on the web where third parties abuse leaked API
keys to use LLMs for free and even charge their "customers" for the privilege!
stopping accidental leakage of 3E002 and other export controlled data through CustomGPT / Actions etc
by geo-segregating key usage within Arm
Getting Started
From the environment you want to create a key for:
1. Go to https://openai-api-proxy.geo.arm.com/ (e.g. from your laptop, or from ETX'd Firefox in an SCE
environment)
2. Click "Create New API Key"
3. Copy the API key and the proxy-endpoint URL to your SDK and connect
If you get an error when attempting to create an API key, this will be because the proxy does not yet know where your
internal Arm IP is. We are working with IT to automate this, but at the moment you need to ask in #help-openai-api.
 The proxy now supports keys for multiple environments and you can have one key per environment.
Attempting to create an additional key in the same environment will overwrite/replace the your previous key for
that environment.

Handling the API Key
Your API-keys are personal to you and thus considered secret.
1. They should not be shared with anyone else, nor put into pipelines and any file you might put it in should only be
readable to you. (0600 permissions in posix environments).
2. They should not be put in the clear on a command line on a shared host where people can see them via e.g. ps
Because it is quite normal for people to give others copies of their shell init files to copy relevant bits out of, we suggest
not putting them in your shell RC files to avoid accidents. Instead, you can set them in the environment by putting the
env declarations in another file (e.g. ~/.secret-env ) and then source-ing that from your init file.
More secure still is to put them in a gpg vault, then create a shell function or script which asks for a given key and then
will take you through the decryption process before returning it to where it can be used in a local variable. However,
many UI tools may not be able to take advantage of this, so secret env is probably the best compromise.
See also Security Principles for Custom GPT Actions and API Integration (under Outbound API Key usage)
OpenAPI Endpoint
Current
https://openai-api-proxy.geo.arm.com/api/providers/openai/v1 ('smart' - will use the right region for your location)
The two legacy region-locked endpoints are
https://openai-api-proxy.geo.arm.com/api/providers/openai-eu/v1 (Non-US)
https://openai-api-proxy.geo.arm.com/api/providers/openai-us/v1 (US)
 The proxy uses Arm's root of trust for its HTTPS certificate. Whilst most machines should already trust this
through (e.g.) curl, some parts of python still don't. There's information on Vault PKI Trust Root detailing how
to fix this. For python code - many python http libraries use certifi , which has its own trust-store. We have a
script here which can be run in your venv to fix this.
Example for the python OpenAI SDK
This uses the official OpenAI python SDK which can be found here https://github.com/openai/openai-python - click for
extended documentation - and is mirrored in Artifactory (please pip install from there - see Using PyPI Mirrors if
you're not sure how!)
The following gives you a simple "hello world" using both the legacy completions and newer responses APIs to OpenAI
in python.
The below code assumes you have already set up a proxy API key for yourself and have it in a local environment
variable OPENAI_API_KEY.
1. Get a good version of python on your path, e.g. via brew install on a Mac, or module load on a cluster
environment.
Suggest python 3.13 but any version 3.11 or higher that does TLS should work.
Keep in mind the minimum version required by the OpenAI module may change over time.
2. Create a python virtual environment (venv)
python3 -m venv --upgrade-deps my-openai-project
3. Install the openai python module
./my-openai-project/bin/pip install openai

Proxy API Keys
The proxy API key you get will only work from a given location. This is intended to be segregated in Arm at the bare
minimum as follows - and are mostly about government data residency compliance:
US vs non-US
3E002 compliant network zones vs not
Your API key will only work when used from the same internal "zone" as it was created.
This is further segregate based on cloud tenancy/project and within clusters, e.g. nahpc vs NASCE vs research islands
vs cloud account; similar to euhpc (sce03, research islands). Lab7 board farms etc.
You can create multiple keys if you do work in different zones (one key per zone).

Instead of running the shell script mentioned above, you can perform all steps directly in Python.
This assumes that your proxy API key is stored in the file: $HOME/.config/arm_openai_proxy/key
from openai import OpenAI
import httpx
import ssl
from pathlib import Path
API_KEY_FILE = Path.home() / ".config/arm_openai_proxy/key"
CA_URL = "https://artifactory.arm.com/artifactory/vault.pki/ent-pki/pem/certs/ARM Enterprise
CA_PATH = Path.home() / ".config/arm_openai_proxy/ARM-Enterprise-PKI-Root-CA.pem"
BASE_URL = "https://openai-api-proxy.geo.arm.com/api/providers/openai/v1"
# Download CA once
if not CA_PATH.exists():
CA_PATH.parent.mkdir(parents=True, exist_ok=True)
r = httpx.get(CA_URL, timeout=30.0)
r.raise_for_status()
CA_PATH.write_bytes(r.content)
ctx = ssl.create_default_context()
ctx.load_verify_locations(cafile=str(CA_PATH))
httpx_client = httpx.Client(verify=ctx)
client = OpenAI(
api_key=API_KEY_FILE.read_text().strip(),
base_url=BASE_URL,
http_client=httpx_client,
)

With my PKI hat on: Please don't "redistribute" the root cert - much as I appreciate the trouble of
posting the above and even putting it in an expand macro! We need to make sure people are getting it
from a known location (Artifactory, or the original IT area, not 'some post on a confluence page'). This
enables us to rotate / keep it up to date sensibly. It also helps foster the right security culture - we
shouldn't be encouraging people to just trust some other location offering the cert.
From a methodology perspective, the above is fine for your own personal scripts, but portable
production code should not assume locations of certs on machines in this way. Instead, either call the
relevant openssl libraries in python to find the correct system root certificate store and pull the
certificate directly from that by its fully qualified subject name, or just curl the thing from the two official
distribution points.
Ideally though this should be set up as part of the environment the script runs in so everybody's code
doesn't have to rely on it.
